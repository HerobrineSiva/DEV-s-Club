HOW TO HANDLE AND RUN THE MACHINE FAILURE PROJECT
=================================================

1. PROJECT FOLDER STRUCTURE
---------------------------

data/train.csv
    Original labelled Track 1 training data. Do not edit this file while
    developing the model.

src/
    All Python source code. The main files to use are modeling.py,
    run_experiment.py, train_final.py, predict.py, and make_submission.py.

tests/
    Automated checks for inference validation and artifact behaviour.

models/
    Created after running train_final.py. It stores the exported joblib model.
    This folder is generated and ignored by Git.

results/
    Created after running run_experiment.py. It stores experiment.json with
    model-comparison metrics, split information, threshold, and holdout
    metrics. This folder is generated and ignored by Git.

README.md
    Main project documentation.

METHODOLOGY.md
    Short Track 1 methodology report for submission.


2. FIRST-TIME SETUP
-------------------

Open PowerShell in this project folder:

  D:\My Codings\First Hackathon\DEV VS codes\DEVS Club

Create a virtual environment:

  python -m venv .venv

Activate it in PowerShell:

  .\.venv\Scripts\Activate.ps1

Install dependencies:

  python -m pip install -r requirements.txt

If PowerShell blocks activation, run this once for the current terminal only:

  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

Then activate the environment again.


3. EXPLORE THE DATA
-------------------

Run:

  python src\explore_data.py

This is safe and read-only. It helps you verify the CSV columns, missing
values, duplicates, target balance, and numeric ranges before training.


4. RUN THE AUTHORITATIVE EXPERIMENT
-----------------------------------

Run:

  python src\run_experiment.py

This is the main experiment command. It does the following:

  A. Loads data/train.csv.
  B. Separates inputs from the Machine failure target.
  C. Creates the same 80/20 stratified development/holdout split every time
     using random seed 42.
  D. Runs five-fold stratified cross-validation on only the development part.
  E. Gets out-of-fold probabilities for all four candidate models.
  F. Ranks models by Average Precision / PR-AUC.
  G. Finds the selected model's F1-optimal threshold using only development
     out-of-fold predictions.
  H. Fits the selected pipeline on development data and reports one local
     holdout evaluation.
  I. Saves all measured values in results/experiment.json.

Do not repeatedly change models after looking at the fixed holdout result.
Doing that turns the holdout into a tuning set and makes its metric less
trustworthy. Use development CV for ordinary model changes.


5. UNDERSTAND THE MAIN FILES
----------------------------

src/modeling.py
    Edit this file only when changing core feature schema, data checks,
    preprocessing, or supported models. Keep FEATURE_COLUMNS in the exact
    order required by the artifact and inference code.

    make_preprocessor() creates the preprocessing pipeline. Numeric columns
    use a median imputer. Logistic Regression additionally uses scaling.
    Type uses a most-frequent imputer and OneHotEncoder.

    make_models() returns new model pipelines. A new pipeline is important:
    sklearn estimators must not be reused after fitting a different fold.

src/run_experiment.py
    Use this for selection and evaluation. The best_threshold() function
    searches 0.05 to 0.95 and chooses maximum F1. The metrics() function
    calculates PR-AUC, F1, precision, recall, and confusion matrix.

src/train_final.py
    Use only after an experiment has selected a model and threshold. It reads
    results/experiment.json, trains the selected model on every labelled row,
    and writes models/machine_failure_model.joblib.

    Training on all rows is correct for deployment after local evaluation, but
    do not claim new independent holdout metrics from this full-data model.

src/predict.py
    Use for general inference on a feature-only CSV. The function predict()
    can also be imported from another Python program.

src/make_submission.py
    Use specifically when the organizers provide their hidden test.csv. It
    creates the final CSV to upload, after you have trained the artifact.


6. EXPORT A DEPLOYMENT MODEL
----------------------------

First ensure the experiment has completed:

  python src\run_experiment.py

Then export the model:

  python src\train_final.py

Expected artifact:

  models\machine_failure_model.joblib

Never manually edit a .joblib file. Regenerate it by re-running the training
command whenever the modelling configuration changes.


7. PREDICT ON A NEW CSV
-----------------------

Create a CSV containing exactly these columns. Their order may be different,
but spelling, spaces, units, and capitalization must match:

  Type
  Air temperature [K]
  Process temperature [K]
  Rotational speed [rpm]
  Torque [Nm]
  Tool wear [min]

Example:

  Type,Air temperature [K],Process temperature [K],Rotational speed [rpm],Torque [Nm],Tool wear [min]
  M,300.1,310.2,1500,40.5,120

Run:

  python src\predict.py new_measurements.csv --output predictions.csv

The output will contain:

  failure_probability
  predicted_failure

failure_probability is a continuous score from 0 to 1. predicted_failure is
0 or 1 after applying the saved threshold (currently 0.26).


8. CREATE THE HACKATHON SUBMISSION FILE
----------------------------------------

When the organizers give you hidden test.csv, do not add the target column to
it. Run:

  python src\make_submission.py path\to\test.csv --output submission.csv

The generated file has two columns:

  Machine failure probability
  Machine failure

PR-AUC requires probability/ranking scores, so use the probability column if
the organizer asks for a single prediction column. Check the final submission
format specified by the hackathon organizers before upload. If they require a
specific target column name, create the output with that exact requested name.


9. RUN TESTS
------------

Run:

  python -m pytest -q

Tests should pass before you submit. Current tests check:

  - model artifact loading;
  - input feature ordering;
  - output shape;
  - probability values stay within 0 and 1;
  - output classes are 0 or 1;
  - missing required columns are rejected;
  - invalid machine Type values are rejected.


10. SAFE CODE CHANGES
---------------------

If changing hyperparameters or adding a model:

  1. Change make_models() in src/modeling.py.
  2. Keep preprocessing inside a Pipeline.
  3. Keep the same fixed holdout boundary unless deliberately beginning a new
     documented experimental protocol.
  4. Run python src\run_experiment.py.
  5. Review results/experiment.json.
  6. Run python -m pytest -q.
  7. If the model is selected, run python src\train_final.py again.

Never fit scalers, encoders, imputers, or resamplers on the full dataset
before cross-validation. This leaks validation-fold information into training.
Never use the hidden organizer test dataset to choose models or thresholds.


11. COMMON ERRORS AND FIXES
---------------------------

"No module named ..."
    Activate .venv and run: python -m pip install -r requirements.txt

"Run src/run_experiment.py first"
    train_final.py needs results/experiment.json. Run the experiment command.

"Missing required feature columns"
    Check CSV spelling against the six required input columns.

"Unexpected feature columns"
    Remove target, ID, index, and unrelated columns from inference CSV.

"Type must be one of ['H', 'L', 'M']"
    Correct the machine type to L, M, or H.

Invalid numeric value error
    Ensure numeric fields do not include text, blank values, NaN, infinity,
    or invalid units. Rotational speed must be positive; tool wear cannot be
    negative.
